# Connect an org that isn't connected

Read this when the builder says their org isn't connected yet, or binding fails for the org they named because its login has expired. Salesforce's own login page does the sign-in: the builder types their password there, and Scout never sees, asks for or stores it. This is the one exception to keeping existing logins unchanged: it adds a login, or renews the same user's, and changes nothing else. Never run a raw `sf org list` or `sf org display` for it; `sf alias list --json` and Scout's binding helper say all it needs.

1. **Offer it in one line,** in plain words: "[Org] isn't connected yet. Shall I open Salesforce's login page in your browser? You sign in there; I never see your password." For an expired login, start with "Your login to [org] has expired" instead. Ask whether it's a sandbox only when the request doesn't say.
2. **On a yes, pick the alias.** For a new org: a short slug without spaces, of the builder's name for it or the customer's (`My Demo Org` becomes `my-demo-org`), because on Windows a quoted alias can break the CLI's launcher; if `sf alias list --json` already has it, pick another, so no existing alias is re-pointed. To renew a login, note the username the alias names, and pass no alias at all.
3. **Open the page.** On Claude, load `salesforce-development:login` first; where it differs, this file wins, and its `sf org display` check is replaced by Scout's binding. Run `sf org login web --instance-url [URL]`, with `--alias [alias]` only for a new org, in the background (on a host without background runs, with a 10-minute timeout). Leave out `--json`, so no token is printed, and never add `--set-default`. The URL is `https://login.salesforce.com`, `https://test.salesforce.com` for a sandbox, or the org's own `https://….my.salesforce.com` when the builder gives it. Tell the builder: "Salesforce's login page is opening in your browser. Sign in there, and I'll continue when you're done."
4. **If no browser can open,** say so, and ask the builder to run the same command in Terminal on the computer this session runs on, so the login is where Scout can use it.
5. **When it finishes,** bind the alias as usual: the binding decides whether the login worked, not the command's exit code (on Windows it can exit 1 after "Successfully authorized"). For a renewal, the bound username must be the one noted in step 2; if the login names another user, say so in plain words, make no further changes and offer to try again; that user's login stays saved, and the alias still names the original user. On a failure, say in plain words what Salesforce reported, and offer to try again, for example with the org's own address. A no changes nothing.
